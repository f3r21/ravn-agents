## Summary
`src/graphql` is the app's GraphQL transport and typed vocabulary: a hand-written `fetch`-based client, domain type aliases, and codegen output generated from `schema.graphql` plus the operations in `src/graphql/operations/`. Feature hooks under `src/features/*` import `request` and the generated `*Document` constants from here rather than talking to `fetch` or a GraphQL library directly. `src/graphql/client.ts:64`

- `src/graphql/domain.ts:31` — re-exports the generated `Task`/`User`/`Status`/`TaskTag`/`PointEstimate`/`UserType` types under domain names; open this before reaching into `generated/graphql.ts` directly.

## How it works
- `request()` builds the POST body as `JSON.stringify({ query: String(document), variables })`, never calling `graphql`'s `print()`; this is what keeps the `graphql` package out of the shipped bundle. `src/graphql/client.ts:78-86`
- Auth header selection is driven by `apiConfig.mode` from `@/lib/env`: `direct` mode adds `Authorization: Bearer <token>`, `proxied` mode adds nothing (the server holds the credential) and produces a different `AUTH_MESSAGE` on 401/403. `src/graphql/client.ts:27-30` `src/graphql/client.ts:78`
- GraphQL's `errors[]` array is checked before `response.ok`, because a 200 response can still carry a user-facing error message; `extensions.code === 'UNAUTHENTICATED'` maps to the same `isUnauthenticated` path as an HTTP 401/403. `src/graphql/client.ts:113-119`
- Feature hooks (`src/features/board/use-tasks.ts:48`, `src/features/board/use-create-task.ts:25`, `src/features/profile/use-profile.ts:22`) call `request(<Document>, variables)` with the generated `*Document` constants and get back the matching `*Query`/`*Mutation` result type — wrong variables or reading an unselected field is a compile error, not a runtime `undefined`.

## Gotchas
- `src/graphql/graphql-stays-out-of-the-bundle.test.ts:47` fails any `src/` file that imports the `graphql` package (by regex over source text); the package is a dev/build dependency only, used by `codegen.ts` and `scripts/check-schema.mjs`, never by app code. Re-adding `print()`/`parse()` to `client.ts` would pass types and lint but should trip this test.
- Files under `src/graphql/generated/` are generated by `npm run codegen` from `schema.graphql` and `src/graphql/operations/*.graphql` (`documentMode: 'string'`, `fragmentMasking: false`); edit the `.graphql` operation files or `schema.graphql`, not `generated/graphql.ts` or `generated/gql.ts` directly. `codegen.ts:16-46`
- `domain.ts` deliberately does not host `BOARD_STATUSES`/`ALL_TAGS`/`ALL_POINT_ESTIMATES` — those are board-UI orderings, not API vocabulary, and live in `features/board/task-types.ts` instead. `src/graphql/domain.ts:25-29`
