`src/app/` is the composition root: it wires the router, error/query providers, and the page-level components that combine features from `src/features/`. ## How it works
- `App` puts the `ErrorBoundary` above `Providers`/`RouterProvider`, not inside a layout route, so a caught error can only be cleared by a full remount (page reload) rather than surviving navigation. `src/app/app.tsx:9-21`
- Routes are flat, each wrapped individually in `<AppLayout>` with its own `errorElement`, instead of children of one layout route — otherwise the not-found page would render inside app chrome that implies the app is fine. `src/app/routes.tsx:17-49`
- Placeholder routes are generated by filtering `NAV_ITEMS` (from `src/features/navigation/app-sidebar.tsx`) for `isPlaceholder: true` and mapping each to a `<PlaceholderPage>` route, so a nav item and its route can never disagree. `src/app/routes.tsx:56-64` `src/features/navigation/app-sidebar.tsx:41-43`
- `MyTaskPage` gates the tasks query on the profile finishing loading: `MyTaskList` only mounts (and only calls `useTasks({ assigneeId })`) once `profile` resolves, so the query never runs with an undefined filter that would briefly show the whole board. `src/app/my-task-page.tsx:37-40` `src/app/my-task-page.tsx:126-150`
- `Providers` creates the `QueryClient` via `useState(() => ...)` rather than a bare call in the render body, so the cache survives re-renders; tests can override it with the `queryClient` prop instead of hitting the network. `src/app/providers.tsx:20-27`

## Gotchas
- `createQueryClient`'s retry logic stops retrying immediately when the error is an unauthenticated `ApiError`, since retrying would just delay showing the auth failure the user needs to see. `src/app/query-client.ts:15-21`
- `MyTaskPage` filters tasks by `assigneeId`, never `ownerId` — `ownerId` matches `Task.creator`, which in the seeded data is the same for every task, so filtering by it would return the entire board instead of a personal list. `src/app/my-task-page.tsx:22-29`
- `PlaceholderPage` is deliberately not `NotFoundPage`: it's used for real, linked, `aria-current`-marked nav destinations that just aren't built yet, and `routes.test.tsx` pins the "This page does not exist" heading as the signal for a genuinely bad URL. `src/app/placeholder-page.tsx:9-20`
